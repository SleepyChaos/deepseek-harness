# Agent Note：窗口会话审计修正

状态：已实现

中文 | [English](2026-08-19-window-session-audit-fixes.md)

## 问题

并发窗口会话分支在工具边界存在四处正确性缺口：预设解析或挂载失败可以被绕过；匿名调用者会变成共享的 `unknown` owner；idle 窗口只返回状态而不返回最终 surface；`window_close({ archive: true })` 只回报归档成功却没有修改持久化的工作区归档集合。外部销毁的 live agent 也可能永久占用预算槽位。

## 决策

将 agent-presets 服务设为强依赖，并在发布子窗口前解析和挂载指定预设。创建和归属校验都要求调用者拥有 live session；子窗口默认继承调用者工作区，窗口标识改用 UUID。无论子窗口 running 还是 idle 都读取 session surface，校验 tail 数量，并在状态刷新时清理外部销毁的条目。请求归档时先通过可选的 workspace registry 持久化，再关闭窗口；归档或销毁失败会返回错误并保留跟踪条目以便重试。

## 验证

窗口会话和完整 URL 的聚焦测试通过，六个文件共 117 项测试全部通过。真实 AgentRegistry 测试现在验证 idle 子窗口仍能读取最终 surface，工具边界测试验证关闭前确实调用持久化归档。

## 影响

并发预设现在必须运行在挂载 `agentPresets` 的宿主中；这从静默空操作变为显式的加载要求。归档功能需要 `workspaceRegistry`；未挂载该服务时请求归档会失败且不会关闭子窗口。

## 备选方案

- **将归档保留为只返回标记。** 拒绝，因为这会违背已记录的归档语义以及持久化工作区注册表的职责。
- **只读取 running 窗口。** 拒绝，因为调度结算需要读取已完成窗口的输出。
- **让预设挂载继续采用尽力而为。** 拒绝，因为这可能发布缺少预设组合或预设不匹配的子窗口。
